# Stability exemptions

`docs/hash-stability.md` §7's plateau rule, as a checked property: every
historical revision of every `.cho` file under `std/` and `examples/`
must type-check under today's compiler, **or** its failing rule appears
here with a reason. `scripts/history.py --explain` enforces it — an
unlisted failing rule is a red CI run; so is a listed rule that fails
**more** revisions than the count recorded below, and so is a listed
rule that stops failing altogether (stale, remove its row). A rule that
fails fewer revisions than recorded is reported, and its count should be
lowered in the same change: the counts only ratchet down.

The failing total stays honest either way: a rule exempted here still
counts toward "do not read"; what the exemption buys is that every
entry of that number has a line in the repository saying why.

Baseline, re-measured at merge of `main` into this branch (cranelift
backend): **210 revisions, 140 do not read** (67%). The three rules
below account for all 140. (The first measurement, at introduction, was
203 and 133: 65%; the seven revisions `main` added since all landed in
`duplicate-declaration`.) The count column is what `history.py --explain`
compares against.

*Re-measured 2026-10-12 after two corrections to the harness, not to
the language: **209 revisions, 99 do not read** (47%), plus 14 revisions
of generated files no longer replayed. `main` had gone red (111
`duplicate-declaration`, 36 `unknown-name`) because the harness counted
things that are not the language moving:*

- *Revisions of generated files (`examples/selfhost/tables.cho` and
  `builtins.cho`, whose headers say `GENERATED by`) were replayed beside
  their siblings, and two generated modules that both import
  `selfhost.driver` collide; every PR that adds a builtin regenerates
  them and added two failures. A generated file's past is derived data,
  not a program, so it is skipped and counted on its own line.*
- *Examples built with packages or with another example's directory
  (`tls_echo`, `https_hello`, `http_fetch_nb`, and the pre-rename
  `net.sockets`/`http.server` examples) were replayed with only their own
  directory, so their imports were "unknown". The harness now adds, from
  the same commit, the file that declared each module the program
  imports (a package wins over an example declaring the same name, as
  `cancho build` is given the package), which is how they were built.*

| rule | count | reason |
|---|---|---|
| duplicate-declaration | 97 | revisions: pre-module-era files that declared the same helper (`sha1`, `hex`) as a sibling; under today's one-module-per-file rule the harness lays them beside each other and the names collide. The files were legal when written; the fix is per-revision (`as` renames), not a language change |
| unknown-name | 1 | revision: `examples/tls_nb/pin_check.cho` at the rename commit imports `destination`, which is `cancho-hooks`' `src/destination.cho` (another repository); it is run with that file named on the command line, as its header says, so no file in this repository declares the module. (Before 2026-10-12 this row was 34: examples importing packages; the harness now adds the declaring files from the same commit) |
| not-a-function | 1 | revision: a pre-enum-era file using a name that is a value, not a call, today |
